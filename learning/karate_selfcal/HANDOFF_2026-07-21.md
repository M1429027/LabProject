> 新對話請將本文件視為唯一上下文。不要依賴舊對話中的口頭假設；若文件內容與實際程式或輸出衝突，先用現有檔案與數據驗證。

## 1. 核心任務

建立不依賴人工外參的多視角、多人物 3D pose estimation pipeline，目標場景為兩位選手對打的空手道場館。

目前要分開處理兩種不同層級的問題：

1. **Camera-level correction**：從 rough extrinsics 修正固定相機的 rotation 與 camera center。
2. **Joint-level refinement**：處理 2D joint correspondence、遮擋、左右肢體錯配與局部 triangulation error。

Camera correction 必須是整段 sequence、所有人物共用；不能為每個人物分別產生不同外參。

## 4. 目前模型架構

模型：`StageARayFusionModel`

輸入為：

```text
B x T x 17 joints x 4 views x 11 features
```

每個 11D ray token：

```text
normalized camera center xyz  3
ray direction xyz             3
normalized pixel xy           2
joint confidence              1
view index                    1
joint index                   1
```

架構：

```text
11D token
  -> MLP embedding, d_model=96
  -> 3-layer per-joint view attention
  -> average joints into per-camera tokens
  -> 2-layer temporal attention over 5 frames
  -> 2-layer cross-camera attention
  -> per-camera correction heads
```

Heads：

- camera origin delta：有套入 corrected triangulation。
- camera rotation delta：有套入 ray direction。
- camera translation delta：有 supervision，但目前推論沒有使用。
- camera scale delta：target 為 0 且目前推論沒有使用。
- no-op gate。
- correction gate。
- pose/pelvis heads 存在，但 `target_space=extrinsic_refine` 時不是目前主要輸出。

Anchor camera 固定為 camera 0，其餘三台輸出 correction。

## 6. 已確認的失敗原因

### 6.1 Gate 資料失衡

v3 的 480 個 sequence variants：

| 類型 | 數量 |
|---|---:|
| Independent random | 266 |
| Empirical structured | 134 |
| Clean/no-op | 72 |
| 真正 pipeline rough | 8 |

約 85% 資料要求模型修正，造成 gate 學成永遠開啟。

### 6.2 Pipeline rough 樣本不足

無遮擋、strict geometry 資料中，60 個 sequences 只有 1 個通過完整 rough-extrinsic validation。模型主要學 synthetic noise，不是實際 matching pipeline 的誤差分布。

### 6.3 Objective 與最終目標不一致

目前 loss 主要監督 camera parameter delta 與 gate；corrected 3D geometry loss 權重只有 0.2。沒有明確要求：

```text
corrected reconstruction 必須優於 rough reconstruction
```

也沒有 non-degradation loss 或可靠的 rough fallback。

### 6.4 Camera correction 粒度錯誤

目前 inference 會對兩位人物分別跑模型，因此同一台固定相機可能因人物不同而得到不同 correction。外參應改成 sequence-level、multi-person shared estimate。

### 6.5 問題層級混淆

Karate 剩餘誤差很可能主要是 joint correspondence、遮擋、左右肢體與 2D localization error。這些是 joint-level error，不能靠移動整台相機修正；camera-level correction 會同時拉偏原本正確的 joints。

### 6.6 Head 與實作不一致

- Translation head 有 loss 但 corrected triangulation 不使用。
- Scale head 不影響 corrected triangulation。
- Camera center 與 translation 被分開預測，可能不符合 `t = -RC`。
- Config 的 `minimum_active_correction: 0.20` 尚未正確傳入 `build_model()`，實際使用預設值 0.15；這是次要問題，但必須修正。

## 7. 已修正的資料問題

曾發現不同 observation caches 中，同名 AMASS motion 使用不同 camera rigs，卻被合併成同一 sequence，破壞固定相機假設。

目前已加入 source namespace，修正後：

- 60/60 sequences 的 camera rig drift 為 0。
- 4,936 samples。
- Dataset integrity check：0 failures。
- Anchor residual：約 `8.4e-8`。

這個 namespace 修正必須保留。

## 9. 接下來固定開發順序

### Step 1：建立不可退步的 Rough Baseline

- Rough triangulation 永遠保留。
- 評估輸出固定比較 GT、rough、corrected。
- Model selection 指標改成 corrected MPJPE 相對 rough 的改善量。
- 若 corrected 不優於 rough，必須自動 fallback 到 rough。

### Step 2：停止目前的 Center Correction

- 先停用 v3 camera-origin head。
- Rotation-only 也只能作 diagnostic，不能直接部署，因為目前仍比 rough 差。
- 不要繼續增加 epoch 或只增加 random synthetic data。

### Step 3：重構為 Sequence-Level Shared Camera Model

- 一段固定機位影片只輸出一組 camera corrections。
- 同時聚合兩位人物、較長時間窗與多個 joints。
- 所有人共享相同的 corrected cameras。
- Anchor camera 保持固定。

### Step 4：統一 SE(3) Parameterization

- 只預測 camera rotation correction 與 camera center correction。
- Translation 使用 `t = -RC` 推導，不再建立獨立 translation head。
- 移除或暫停未實際使用的 scale head。
- 修正 `minimum_active_correction` config 傳遞。

### Step 5：加入 Safety Gate / Non-Degradation Objective

- Gate 不能只依據 synthetic GT delta 學習。
- 使用 held-out frames 的 reprojection、ray consistency、triangulation conditioning 或 geometry score判斷 correction 是否真的改善。
- 加入 corrected 不得比 rough 更差的 hinge/ranking loss。
- No-op/clean cases 比例提高到至少 40–50%。

### Step 6：增加真實 Pipeline-Rough Training Cases

- 優先改善 geometry validation 通過率與保存通過的 sequence-level rough estimates。
- 訓練資料必須包含 matching pipeline 真正會產生的 error pattern。
- 不可用大量 independent random noise 取代 pipeline rough。

### Step 7：Camera Correction 穩定後再做 Joint-Level Refinement

- 處理 joint correspondence、左右肢體、遮擋與 local 2D error。
- 使用 per-joint confidence、view subset、temporal consistency 與 rough 3D residual。
- Joint refiner 不得反過來偷偷修改整套 camera extrinsics。

## 10. 每一步的驗收規則

- 一次只改一個主要因素。
- 每一步都先跑 synthetic/formal test，再跑同一個 Karate 004 case。
- 所有比較使用相同影片、GT、座標系、similarity alignment 與 joint mask。
- 必須輸出 GT / rough / corrected 三欄影片。
- 指標至少包含 rough MPJPE、corrected MPJPE、改善百分比、coverage、gate 與 correction magnitude。
- 若模型結果不優於 rough，立即停止下一階段並診斷，不得只用總 loss 宣稱改善。
